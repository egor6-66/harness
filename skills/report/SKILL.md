Отчёт по задаче — **в тот пункт `ROADMAP.yaml`, откуда пришло ТЗ**, а не в чат. Файл лежит рядом
с кодом и доезжает до каждого, кто клонировал репозиторий; чат уедет из контекста.

До отчёта прогони проверки и возьми их ФАКТИЧЕСКИЙ результат, а не ожидаемый:

```bash
pnpm lint && pnpm typecheck && pnpm test
```

Красное — так и пиши. Отчёт о непроверенной работе дороже отсутствия отчёта: на нём принимают
решения.

Что дописывается в `description` пункта:

- **что сделано** — по существу, без парада шагов;
- **что изменено** — файлы и ветка;
- **чем подтверждено** — какие проверки прогнаны и с каким результатом;
- **что НЕ сделано и почему** — блокеры, упёршееся;
- **версия пакета** — менял поставляемое содержимое, назови, какую считаешь правильной (патч —
  правки текста и дефолтов, минор — новый артефакт или изменение состава полей). Сам не
  поднимаешь: это делает выпуск.

`status` пункта двигаешь по факту: работа закрыта — `Done`, упёрлась — остаётся `Open` с
названным блокером.

**Чужой дефект в свой пункт не смешивай** — у смешанного перечня нет адресата, который может его
принять. Назови его отдельно, чтобы architect завёл пункт владельцу.

В чат — одна строка: где отчёт и какой статус.

Пункт: $ARGUMENTS
