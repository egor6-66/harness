# communication — как общаться с user'ом

> Общее правило для всех ролей и всех репозиториев. Каждое правило — что делать, почему и пример.

## Правила

### 1. Без простыней: по теме за раз

Тем несколько — по каждой одна-две фразы, главное. Подробно разбираем только ту тему, которую
выбрал user, и по одной за раз. Разные темы в одном разборе не смешиваются.

**Почему:** простыню не читают, решение по ней не принимается, а работа встаёт там, где ждали ответа.

Так:
> Три вещи:
> 1. Вход работает, проверил на живом бэке.
> 2. Бэк отдаёт ошибки в двух форматах — нужна правка у них.
> 3. Экран деталки ждёт адрес ручки.
>
> С чего начнём?

Не так: три экрана текста, где все три темы разобраны вперемешку, с вариантами и примерами кода по
каждой сразу.

### 2. Варианты — текстом, не таблицей

Варианты, сравнения, планы — нумерованным списком: каждый пункт отдельно и проговорён словами. Таблиц
с вариантами нет.

**Почему:** таблица сжимает рассуждение до клеток — непонятно, что из чего следует и что советуешь.

Так:
> 1. Панель справа — список остаётся перед глазами. Советую это.
> 2. Отдельная страница — на весь экран, с возвратом назад.

Не так:
> | Вариант | Плюсы | Минусы |
> |---|---|---|
> | Панель | … | … |

## Порядок работы

### 3. Правка — по 1-2 файла, дальше ревью

Пишешь 1-2 файла и останавливаешься: user смотрит, вопросы обсуждаем, потом следующий шаг. Много
файлов за раз — только когда user дал на это ок и правка однотипная (переименование, одна и та же
замена). Тогда в конце — список: какой файл что получил.

**Почему:** маленький шаг user успевает прочитать и поправить, пока решение дёшево менять. Большой
вываливается целиком, и половину приходится откатывать.

Так:
> Сделал `use/catalog.ts` — хук отдаёт разделы без пустых. Посмотри; если ок — переведу на него
> страницу.

Не так: за один ход новый модуль, стор, хук, компонент, страница и маршрут — десять файлов, о которых
user узнаёт из итогового отчёта.

### 4. Тесты и дока — после согласования

Тесты и доку пишешь, только когда конечный результат согласован и user сказал, что вид закреплён. Пока
идёт поиск — код и проверки (линт, типы, сборка), без тестов и доки.

**Почему:** форма меняется на каждом шаге поиска, и тесты с докой пришлось бы переписывать каждый
раз — это работа впустую.

Так: «Вид закрепили — пишу тесты на хук и раздел в README».

Не так: к каждому промежуточному варианту — свой тест, который через два шага уже неверен.
